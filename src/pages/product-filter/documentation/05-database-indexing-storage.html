4. Database Indexing, Storage & Sorting

High-volume WooCommerce stores frequently suffer catastrophic query degradation when filtering across multiple custom product attributes, price bands, stock states, and ratings. Standard WooCommerce architectures execute 4× to 8× nested relational joins against the unindexed Entity-Attribute-Value (EAV) table wp_postmeta. Pickory eliminates this bottleneck entirely by pre-computing all facet dimensions into two dedicated, high-performance B-tree indexed storage tables: wp_ppfx_product_index and wp_ppfx_product_terms.

FLAT INDEX COMPOSITE B-TREE ATOMIC UPSERT CURSOR SYNC QUERY CACHE O(1) INVALIDATION
DENORMALIZATION

Flat Product Index (ppfxi)

Collapses volatile numerical metrics (min/max price, on-sale flag, average star rating, stock status) into a single denormalized table with zero EAV join overhead.

COVERING INDEX

Taxonomy Terms Index (ppfxt)

Dedicated relational term map with 3-column covering index (taxonomy, term_id, product_id) enabling MySQL to resolve multi-attribute criteria directly in memory.

CACHE VERSIONING

Microtime Key Invalidation

Global query cache versioning decouples persistence from cache eviction storms. Modifying a single product bumps the global timestamp, invalidating all query keys in O(1) time.

5.1 STORAGE SCHEMA

Flat Index Schema (wp_ppfx_product_index)

Managed by PPFX_Index_Schema::create_table() in includes/index/class-ppfx-index-schema.php, the flat index table (aliased as ppfxi in compiled SQL) stores atomic product-level filtering criteria:

Column Name SQL Data Type Default Indexing & Constraints Architectural Responsibility
product_id bigint(20) unsigned None PRIMARY KEY Matches wp_posts.ID. Guarantees exactly one row per parent catalog product.
min_price decimal(10,2) 0.00 KEY idx_min_price Lowest purchasable variation price or simple product regular/sale price. Fixed decimal eliminates floating-point rounding errors.
max_price decimal(10,2) 0.00 KEY idx_max_price Highest purchasable variation price. For simple products, max_price === min_price.
on_sale tinyint(1) 0 KEY idx_on_sale Boolean flag (1 or 0). Calculated dynamically across all child variations or parent discounts.
avg_rating decimal(3,2) 0.00 KEY idx_avg_rating Aggregated customer review rating (e.g. 4.75). Enables rapid minimum rating thresholds (>= 4.0).
stock_status varchar(20) 'instock' KEY idx_stock_status Standardized WooCommerce inventory enum ('instock', 'outofstock', 'onbackorder').

The DDL specification is executed via WordPress dbDelta() during plugin activation or schema version upgrades: 

CREATE TABLE {$wpdb->prefix}ppfx_product_index (
  product_id bigint(20) unsigned NOT NULL,
  min_price decimal(10,2) NOT NULL DEFAULT 0.00,
  max_price decimal(10,2) NOT NULL DEFAULT 0.00,
  on_sale tinyint(1) NOT NULL DEFAULT 0,
  avg_rating decimal(3,2) NOT NULL DEFAULT 0.00,
  stock_status varchar(20) NOT NULL DEFAULT 'instock',
  PRIMARY KEY  (product_id),
  KEY idx_min_price (min_price),
  KEY idx_max_price (max_price),
  KEY idx_price_range (min_price, max_price),
  KEY idx_on_sale (on_sale),
  KEY idx_avg_rating (avg_rating),
  KEY idx_stock_status (stock_status),
  KEY idx_stock_product (stock_status, product_id)
) {$collate};
5.2 RELATIONAL INDEX

Term Index Schema (wp_ppfx_product_terms)

Managed by PPFX_Index_Schema::create_term_table(), the taxonomy-term table (aliased as ppfxt in compiled SQL) flattens product relationships across categories, tags, catalog visibility flags, and global product attributes (e.g. pa_color, pa_size, pa_brand):

Column Name SQL Data Type Indexing & Constraints Architectural Responsibility
id bigint(20) unsigned PRIMARY KEY AUTO_INCREMENT Unique row identifier for strict row-level pointer integrity.
product_id bigint(20) unsigned KEY idx_product Foreign product ID reference. Targeted during atomic term synchronization and product deletion.
taxonomy varchar(128) Compound Keys Public taxonomy identifier (e.g. product_cat, pa_color, product_visibility).
term_id bigint(20) unsigned Compound Keys WordPress wp_terms.term_id integer key. B-tree indexed for instantaneous equality checks.

The table enforces a composite unique constraint to guarantee zero duplicate term mappings per product: 

CREATE TABLE {$wpdb->prefix}ppfx_product_terms (
  id bigint(20) unsigned NOT NULL AUTO_INCREMENT,
  product_id bigint(20) unsigned NOT NULL,
  taxonomy varchar(128) NOT NULL,
  term_id bigint(20) unsigned NOT NULL,
  PRIMARY KEY  (id),
  UNIQUE KEY uniq_product_tax_term (product_id, taxonomy, term_id),
  KEY idx_product (product_id),
  KEY idx_taxonomy_term (taxonomy, term_id),
  KEY idx_tax_term_product (taxonomy, term_id, product_id)
) {$collate};
5.3 INDEX ARCHITECTURE

Composite Index Strategy & Column Types

The physical layout of MySQL indexes dictates whether a query executes via an in-memory B-tree index scan or falls back to an expensive disk-bound temporary table and filesort operation. Pickory implements tailored composite indexes designed specifically around catalog filtering access patterns:

Index Name Table Indexed Columns Execution Optimization
idx_price_range ppfxi (min_price, max_price) Satisfies dual-bound price slider queries (min_price >= X AND max_price <= Y) in a single contiguous B-tree range scan.
idx_stock_product ppfxi (stock_status, product_id) Enables instantaneous index-only filtering for in-stock catalog products without touching table data pages.
idx_tax_term_product ppfxt (taxonomy, term_id, product_id) Covering Index: MySQL satisfies both the WHERE taxonomy = %s AND term_id IN (...) clause and the JOIN ppfxt.product_id = wp_posts.ID straight from the index tree without row pointer dereferencing.
uniq_product_tax_term ppfxt (product_id, taxonomy, term_id) Prevents multi-worker concurrency race conditions from inserting redundant attribute rows during bulk imports.
[ENGINEERING RULE]

Fixed-Point Decimal Precision (decimal(10,2))

Floating-point data types (FLOAT, DOUBLE) introduce binary rounding imprecisions (e.g. 19.990000000000002), causing price slider boundary queries (min_price >= 19.99) to intermittently exclude products. All price columns in Pickory strictly enforce decimal(10,2) to guarantee exact monetary arithmetic.
5.4 REAL-TIME SYNC

Real-Time Product Sync Lifecycle

Whenever product attributes, prices, or inventory levels mutate in WooCommerce, PPFX_Product_Indexer (includes/index/class-ppfx-product-indexer.php) synchronizes both index tables in real time:

WooCommerce Event / Hook Invoked Method Sync Execution Details
save_post_product
woocommerce_update_product		 sync_product($product_id) Calculates variable bounds, runs atomic $wpdb->replace() on ppfxi, synchronizes term rows in an explicit MySQL transaction, and purges price transients.
woocommerce_new_product sync_product($product_id) Inserts new flat index record and term mappings, then bumps the shared query cache version.
delete_post
woocommerce_delete_product		 delete_product($product_id) Deletes matching rows from both ppfxi and ppfxt by product_id, purges price cache, and bumps query cache version.
woocommerce_product_set_stock_status sync_product($product_id) Instantly updates stock_status column when inventory depletes via order placement.
VARIABLE BOUNDS

Variable Product Calculation

For WC_Product_Variable products, the indexer queries $product->get_variation_prices(true), computing the exact lowest variation price, highest variation price, collective stock status, and collective sale status.

ATOMIC TRANSACTIONS

Term Sync Transaction Boundary

Term replacement executes inside an isolated database transaction: START TRANSACTION → DELETE FROM ppfxt WHERE product_id = %d → Bulk INSERT → COMMIT. On failure, ROLLBACK prevents partial term records.

5.5 BATCH & CLI OPS

Bulk Reindexing & CLI Locks

During initial installation or catalog-wide migrations, PPFX_Product_Indexer::bulk_sync() rebuilds both index tables from scratch using high-speed chunked batch processing:

Pipeline Phase Mechanism Architectural Protection
Concurrency Lock set_transient('ppfx_bulk_sync_lock', 1, 600) Prevents concurrent admin requests or cron jobs from running overlapping reindexes. Automatically released in a try...finally block.
Table Truncation TRUNCATE TABLE {$table} Instantly resets auto-increment counters and purges old data without slow row-by-row deletes.
Keyset Pagination WHERE ID > %d ORDER BY ID ASC LIMIT 200 Bypasses OFFSET performance decay. On a 100,000 product catalog, page 500 executes as fast as page 1.
Verification & Flag PPFX_Index_Schema::mark_built() Validates total indexed rows against published product counts and sets ppfx_index_built = 1 in wp_options. 
// Keyset Pagination Cursor Loop
$last_id = 0;
$batch   = 200;
do {
    $ids = $wpdb->get_col( $wpdb->prepare(
        "SELECT ID FROM {$wpdb->posts} WHERE post_type = 'product' AND post_status = 'publish' AND ID > %d ORDER BY ID ASC LIMIT %d",
        $last_id,
        $batch
    ) );
    foreach ( $ids as $id ) {
        self::sync_product( (int) $id, false );
    }
    if ( ! empty( $ids ) ) {
        $last_id = (int) end( $ids );
    }
} while ( count( $ids ) === $batch );
5.6 PERSISTENT CACHE

Persistent Query Cache Tier (PPFX_Query_Cache)

Located in includes/services/class-ppfx-query-cache.php, this subsystem decouples SQL query compilation from cache persistence. To maximize Redis and Memcached hit rates, Pickory employs an ID-Only Caching Architecture:

LIGHTWEIGHT PAYLOAD

ID-Only Array Storage

Instead of serializing heavy WC_Product objects or rendered HTML fragments into Redis, Pickory caches only matching post ID arrays (e.g. [102, 105, 118]), found_posts, and max_num_pages.

DYNAMIC HYDRATION

hydrate_query() Engine

Reconstructs a live WP_Query instance using 'post__in' => $cached_ids, 'orderby' => 'post__in', and restores pagination metadata. Dynamic cart rules, live currency switchers, and user-specific pricing apply seamlessly.

Cache keys are generated deterministically by normalizing and alphabetically sorting all incoming criteria: 

// Deterministic Cache Key Formula
$key = 'ppfx_query_' . PPFX_Query_Cache::get_query_cache_version() . '_' . md5( wp_json_encode( $normalized_params ) );
5.7 CACHE INVALIDATION

Cache Key Hashing & Invalidation on Save

Standard caching plugins flush entire Redis databases or iterate through thousands of wildcard keys (e.g. KEYS ppfx_query_*) during product updates, causing severe CPU spikes and blocking single-threaded cache engines. Pickory solves this with O(1) Versioned Group Invalidation:

Component Mechanism Performance Characteristic
Version Storage update_option('ppfx_query_cache_version', (string) microtime(true)) Stored in wp_options (autoloaded). Single scalar integer/float mutation.
Invalidation Cost O(1) Constant Time Zero keyspace iterations. Previous cached keys immediately become orphaned and are evicted naturally by Redis LRU policy.
Session Bypass Guard has_dynamic_session() Bypasses caching when a customer has items in their cart (!WC()->cart->is_empty()), is logged in, or has active session discount coupons.
Nightly Sale Cron PPFX_Index_Scheduler::sync_expired_sales() Runs daily via ppfx_sync_expired_sales cron to gracefully update items whose scheduled sale period ended at midnight.
