The codebase adheres to a strict separation of concerns across the PHP/JavaScript boundary. The backend isolates data management, query compilation, and REST endpoints into modular PSR-compliant classes, while the frontend is structured as state-decoupled ES6 modules built via Vite:

src/js/components/ Reactive Client Layer Zero-dependency UI controllers: filter-form.js (form controller), active-filters.js (chip manager), filter-globals.js (instance registry), price-slider.js, and mobile-drawer.js.

1.2 ARCHITECTURE

The Dual-Path Execution Model (SSR vs. AJAX)

To guarantee zero cumulative layout shift (CLS) for human visitors and complete content visibility for search engine crawlers, Pickory executes via two deterministic execution pipelines:

PATH A: SERVER-SIDE (SSR)

Initial Page Load & Crawlers

Executed by PPFX_Server_Filter. Binds to WordPress core pre_get_posts on WooCommerce catalog archives. It reads public ppfx_ query variables directly from the global request, rewrites the main query using the flat index, and delivers pre-filtered HTML before client JavaScript executes.

PATH B: CLIENT-SIDE (AJAX)

Reactive User Interactions

Executed by PPFXURLStateManager and REST fetchers. User gestures immediately mutate the browser URL, dispatch synthetic ppfx:url-change events, abort pending in-flight requests, and fetch surgical HTML fragments from /pickory-filter/v1/products to update DOM containers without page reload.

[DETERMINISTIC FIDELITY]

SSR and AJAX Parity Invariant

Both Path A and Path B delegate to the same underlying PPFX_Query_Clause_Compiler SQL compiler. Whether a filtered catalog URL is loaded freshly via hard browser reload or transitioned into via client clicks, the returned product set and pagination counters are mathematically identical.
1.3 CONVENTIONS

The ppfx_ Namespace Convention

To eliminate collision vectors with WordPress core query variables, theme parameters, and companion WooCommerce extensions, Pickory enforces an immutable prefix contract across every subsystem:

Domain Namespace Pattern Concrete Implementation Examples
PHP Classes & Constants PPFX_* / ppfx_* PPFX_Product_Indexer, PPFX_VERSION, PPFX_INDEX_VERSION, ppfx_bootstrap()
Database Tables {$wpdb->prefix}ppfx_* wp_ppfx_product_index (aliased as ppfxi), wp_ppfx_product_terms (aliased as ppfxt)
Public URL Query Parameters ppfx_{facet} ppfx_category, ppfx_min_price, ppfx_max_price, ppfx_rating, ppfx_stock, ppfx_on_sale, ppfx_attr_{taxonomy}
Custom DOM Events ppfx:* / ppfx_* ppfx:url-change, ppfx-filters-updated, ppfx_products_rendered, ppfx:ajax_loaded, ppfx:destroy
Localized JS Global window.ppfxFilterData Exposes REST root, nonce, currency symbols, archive context, localized labels, and section manifests.
1.4 INTEGRATION

WooCommerce Integration Surface

Pickory operates as a native extension of WooCommerce rather than an isolated external layer. It integrates cleanly with core hooks and respect store configurations:

CORE COMPATIBILITY

HPOS Custom Order Tables

Declares full compatibility with WooCommerce High-Performance Order Storage via FeaturesUtil::declare_compatibility('custom_order_tables', __FILE__, true).

HOOK INTERCEPTION

Priority 20 Execution

Hooks woocommerce_product_query and posts_clauses at Priority 20 to safely intercept queries after WooCommerce core Priority 10 orderby and visibility mutations.

LIFECYCLE HOOKS

Real-Time Synchronization

Monitors woocommerce_product_object_updated_props, woocommerce_trash_product, and stock update hooks to trigger immediate atomic index refreshes and cache invalidations.

1.5 DATA PIPELINE

Data Flow: Browser → REST → Query → Fragment → DOM

Dynamic filter interactions follow a unidirectional reactive loop across 6 discrete architectural stages:

Stage Component Operational Responsibility
1. Ingestion filter-form.js Captures user gestures (swatch clicks, checkbox toggles, dual-slider drag). Debounces continuous slider updates at 300ms.
2. Serialization url.js (PPFXURLStateManager) Maps internal facet keys to public ppfx_ parameters. Commits state to browser history via pushState() or replaceState().
3. Event Broadcast window (EventBus) Dispatches custom synthetic event ppfx:url-change with active parameters, synchronizing desktop sidebar and mobile drawer widgets.
4. REST Transport api.js & Products_Controller Initiates abortable fetch to /wp-json/pickory-filter/v1/products with nonce validation and token bucket rate limiting (80 req/min).
5. Query & Cache Query_Builder & Query_Cache Computes normalized MD5 key in persistent object cache. On cache miss, compiles optimized SQL against wp_ppfx_product_index via Priority 20 hook scope.
6. Fragment Patch Fragment_Renderer & DOM Renders isolated HTML fragments (products loop, pagination, chip container). Client replaces target DOM containers, manages ARIA live states, and fires ppfx_products_rendered.

Class Responsibility Map

The table below maps the core PHP classes and JavaScript modules to their single architectural responsibilities:
