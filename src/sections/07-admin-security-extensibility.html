// Term Meta Persistence Security Guard

7.3 RATE LIMITING

Token Bucket Rate Limiter

Located in includes/services/class-ppfx-rate-limiter.php, PPFX_Rate_Limiter protects the REST endpoint against scrapers and denial-of-service attempts:

IP SPOOFING DEFENSE

Robust Client IP Detection

Prioritizes Cloudflare's HTTP_CF_CONNECTING_IP. Validates addresses with FILTER_FLAG_NO_PRIV_RANGE | FILTER_FLAG_NO_RES_RANGE. Generic headers (X-Forwarded-For) require explicit opt-in via PPFX_TRUST_PROXY.

MEMORY EFFICIENCY

Atomic Object Cache Tier

When Redis or Memcached is active (wp_using_ext_object_cache()), rate counters increment atomically via wp_cache_incr(). Automatically bypasses database transient writes to eliminate wp_options bloat. 

// Atomic Cache Rate Check
$hit_count = wp_cache_incr( $transient_key, 1, 'pickory-product-filter' );
if ( false === $hit_count ) {
    wp_cache_set( $transient_key, 1, 'pickory-product-filter', $window_in_seconds );
    $hit_count = 1;
}
return $hit_count > $max_hits; // Returns true when rate exceeded

7.5 CLIENT HARDENING

Prototype Pollution Defenses

URL parameter parsing is a common vector for Prototype Pollution attacks in JavaScript applications. If an attacker injects query keys like ?__proto__[isAdmin]=true or ?constructor[prototype][polluted]=yes, naive object assignment mutates the global Object prototype.

[DEFENSIVE INVARIANT]

Key Denylist in src/js/utils/url.js

Both toPublicParams() and toInternalParams() enforce an unconditional guard that discards hazardous property keys before any object mutation takes place: 
if (key === '__proto__' || key === 'constructor' || key === 'prototype') return;

Additionally, dynamic CSS selector matching uses cssEscape() to sanitize attribute values before querying the DOM, neutralizing CSS injection exploits: 

// Safe CSS Selector Escaping
export const cssEscape = (value) => {
  const stringValue = String(value);
  if (window.CSS && typeof window.CSS.escape === 'function') {
    return window.CSS.escape(stringValue);
  }
  return stringValue.replace(/[^a-zA-Z0-9_-]/g, '\\$&');
};
7.6 PERFORMANCE GUARDRAILS

Memory Thresholds & Guardrails

Engineers extending or deploying Pickory in large-scale enterprise environments must adhere to strict runtime boundaries:

[GUARDRAIL 1]

Direct postmeta joins strictly prohibited

All frontend product filtering queries must resolve exclusively against wp_ppfx_product_index and wp_ppfx_product_terms. Bypassing the flat index to execute raw WP_Query meta queries in catalog loops causes catastrophic table locks and CPU saturation during flash-sale spikes.
[GUARDRAIL 2]

Batch Reindexing Memory Thresholds

When executing CLI re-indexing (wp pickory reindex) on catalogs exceeding 50,000 SKUs, always specify keyset batch sizing (--batch-size=200) and sleep pauses (--sleep=2) to prevent Redis object cache eviction storms and PHP memory limit exhaustion.
