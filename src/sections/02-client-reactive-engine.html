2.1 ARCHITECTURAL INVARIANT

The URL as Single Source of Truth

In complex WooCommerce themes, filter controls frequently exist simultaneously across multiple DOM subtrees: a desktop sidebar, a mobile off-canvas drawer, a top-bar sort dropdown, and breadcrumb chips. Traditional filtering plugins store filter state in component-level memory or ad-hoc jQuery objects, leading to synchronization drift, duplicate REST fetches, and broken browser history.

Pickory resolves this by declaring the browser window URL search parameters as the sole authoritative state container. Components possess zero independent filter state; they act strictly as readers and writers of the canonical URL string:

Dimension Traditional In-Memory Store Pickory URL SSOT Architecture
Authority Component state / JS variables in memory Browser address bar (window.location.search)
Multi-Widget Sync Imperative DOM event spaghetti across widgets Automatic reactive hydration via syncAllUIs()
History Navigation Requires custom state serialization & stack recovery Native popstate listener re-hydrates UI automatically
Shareability State is lost on copy/paste or page refresh 100% deterministic link fidelity with SSR parity
2.2 OBSERVER CONTRACT

PPFXURLStateManager — Observer Contract & Event Bus

Located in src/js/utils/url.js, the PPFXURLStateManager class manages the observer registry and event bus. It exports a singleton instance, PPFX_URL_State, that decouples UI widget controllers from network fetchers:

OBSERVER REGISTRY

subscribe(listener)

Accepts a callback function fn(params, detail) and registers it within an internal Set. Returns a clean unsubscription closure to prevent memory leaks during component destruction.

EVENT BUS

ppfx:url-change

Whenever the canonical state transitions, the manager dispatches a native CustomEvent('ppfx:url-change') with { detail: { params, source, url } } to the global window object.

CANONICAL READER

getCanonicalState()

Synchronously reads window.location.search, converts public ppfx_ query variables into internal parameter objects, and returns an immutable state snapshot.

2.4 UNIDIRECTIONAL WRITE GATE

commitFilterUpdate — The Unidirectional Write Gate

To maintain absolute determinism, no UI component directly calls window.history.pushState(). Instead, all mutations in filter-form.js must pass through the commitFilterUpdate gate:

1. Read Current PPFX_URL_State.getCanonicalState() Reads the existing parameters directly from the browser URL address bar.
2. Clone State next = { ...current } Creates a detached copy to ensure state mutations are isolated and transactional.
3. Automatic Page Reset delete next.page; delete next.paged; If resetPage: true (default), clearing pagination guarantees the user lands on page 1 of new filter results.
4. Execute Mutator modifierFn(next) Applies specific facet additions, deletions, or range changes to the mutable clone.
5. Gate Evaluation if (isAutoFilter || source === "submit") In auto-filter mode, commits immediately to URL. In manual submit mode, holds staging state until submit is clicked.
2.5 HISTORY API STRATEGY

setCanonicalState — History Push vs. Replace Strategy

The setCanonicalState method constructs a clean URL object, purges obsolete ppfx_* keys, and writes the new query string using an intentional history management strategy:

PUSH STATE (pushHistory: true)

Discrete User Selections

Used for distinct user choices (clicking category checkboxes, color swatches, star ratings, or pagination links). Creates a new entry in the browser session history so users can click the browser Back button to revert the selection.

REPLACE STATE (pushHistory: false)

Continuous Inputs & Normalization

Used during dual-thumb price slider drag movements, text search debounces, or initial boot normalization. Replaces the current history entry in-place to avoid polluting the browser history with dozens of micro-step drag entries.

[NON-FILTER PRESERVATION]

Preservation of Foreign Parameters

setCanonicalState() only purges known filter keys and ppfx_ prefixed parameters. Foreign query parameters (such as marketing UTM tags utm_source, affiliate tokens, or WordPress search s) are strictly preserved across state transitions.
2.6 BROWSER NAVIGATION

popstate Handling & Browser Back/Forward Integration

When a user clicks the browser Back or Forward button, the browser triggers a native popstate event. Pickory intercepts this via an immutable lifecycle loop:

  1. _initPopstate() listener receives the native popstate event from the window.
  2. Calls getCanonicalState() to parse the newly active URL search string.
  3. Dispatches ppfx:url-change with source: 'popstate' and the event's history state.
  4. The state coordinator receives the event and initiates an AJAX fragment fetch matching the historical URL.
  5. History Cycle Protection: Because the navigation was initiated by the browser itself, the coordinator never calls pushState() or replaceState(), avoiding infinite loop traps.

2.8 KEY PARTITIONING

Reserved Key Partition: Filters vs. Sort & Pagination

Not all parameters in the URL represent product facets. Pickory establishes a strict key partition through RESERVED_FILTER_KEYS:

FACET KEYS

Criteria Modifiers

category, product_tag, min_price, max_price, rating, on_sale, and dynamic filter_* attributes. Mutating any facet key triggers an automatic reset of pagination (page=1) and recalculates facet term counts.

RESERVED KEYS

Traversal & Presentation

orderby, order, page, paged, ppfx_instance_id. Mutating reserved keys changes catalog presentation or pagination page without altering facet boundaries or generating active filter chips.

3.3 MUTATION PRIMITIVES

toggleMultiValue vs. setSingleValue — State Mutation Primitives

All interactive inputs channel their state changes through two foundational primitives that manage serialized array vs. scalar facet states:

MULTI-VALUE PRIMITIVE

toggleMultiValue(name, value, isChecked)

Used by checkboxes, color swatches, and button grids. Deserializes existing comma-separated terms into a Set, adds or removes the target slug, re-serializes as a sorted, deduplicated string, and purges the key if empty. Automatically triggers a pagination reset.

SCALAR PRIMITIVE

setSingleValue(name, value, options)

Used by radio buttons, dropdown selects, star ratings, and toggle switches. Assigns the scalar string directly or completely deletes the key if value is empty, null, or "0". Supports custom history push/replace flags.

[SECURITY & RESERVED KEY GUARD]

Mutation Boundary Enforcement

Both primitives enforce an immediate return guard if name matches prototype keys (__proto__, constructor, prototype) or falls within the RESERVED_FILTER_KEYS set (orderby, order, page), preventing accidental pollution of core traversal properties.

3.6 UX PATTERN

Radio Uncheck Toggle Pattern

In native HTML, radio buttons are latching inputs: once selected, clicking an already-checked radio button does nothing. This produces poor UX in faceted search when users wish to deselect a singular facet option without clicking a global reset button.

Pickory solves this via a pre-change click interceptor tracking transient selection states through target.dataset.wasChecked:

  1. A delegated click listener intercepts clicks on input[type="radio"] before the change event fires.
  2. If target.dataset.wasChecked === "true", the user is clicking an already-active radio:
    • Forces target.checked = false.
    • Sets target.dataset.wasChecked = "false".
    • Calls setSingleValue(target.name, "") to purge the parameter from state.
  3. Otherwise, sets target.dataset.wasChecked = "true" and resets companion sibling radios in the same group to wasChecked = "false".
3.7 FORM SERIALIZER

Form Serialization for Manual Submit Mode

When isAutoFilter: false is configured, widget interactions mutate internal input staging states without altering the canonical URL. When the user clicks "Apply Filters", serializeFormState() compiles the entire form snapshot:

  1. Gathers all checked input[type="checkbox"], grouping common names into comma-delimited arrays.
  2. Gathers checked input[type="radio"] and non-empty select:not([name="orderby"]) values.
  3. Extracts values from hidden inputs corresponding to custom button grids, swatches, star ratings, and toggle switches.
  4. Inspects price slider inputs: if prices differ from default boundary datasets (data-min, data-max), serializes min_price and max_price.
  5. Preserves existing sort order (orderby, order) from canonical URL state.
  6. Purges pagination (page, paged) and commits to URL via setCanonicalState(state, { pushHistory: true, source: "submit" }).
3.8 IDEMPOTENT HYDRATION

applyFilterState — Idempotent UI Hydration Engine

When the URL changes via browser navigation or secondary widgets, applyFilterState(formElement, filters) reconciles all form controls without destructive side-effects. It enforces strict non-interference guards:

FOCUS PRESERVATION

Active Element Guard

Compares elements against document.activeElement. If a user is actively typing in a search input or has an open dropdown select, the hydration engine skips value reassignment or restores caret selection ranges (setSelectionRange).

SLIDER DRAG PROTECTION

Active Thumb Protection

If either min or max price input currently possesses keyboard or pointer focus, background hydration does not disrupt the active thumb handle or overwrite transient input values.

3.9 BOUND DETECTION

Price Slider State & Default Bound Detection

A major source of query bloat in WooCommerce filtering is sending price constraints that match the catalog's absolute min/max limits (e.g. min_price=0&max_price=500 when all products fall within that range).

Pickory solves this via isPriceAtDefaultBounds(formElement, params):

  • Reads dataset bounds data-min and data-max from the parent .ppfx-price-group container.
  • Compares current values against these bounds.
  • If currentMin === minBound && currentMax === maxBound, the price parameters are completely deleted from the request payload and URL query string.
  • Bypasses unnecessary SQL price range clauses entirely, allowing the database query to execute without indexed price comparisons.
3.10 SORT SYNCHRONIZATION

applySortState — Sort Dropdown Sync Across Contexts

The applySortState(root, sort) utility synchronizes WooCommerce catalog ordering dropdowns (select[name="orderby"], select.orderby, .woocommerce-ordering select) across both sidebar widgets and main loop toolbars:

  • Escapes target orderby values with cssEscape() before executing DOM queries.
  • Matches target values against child <option> elements.
  • Safe Fallback: If target orderby is empty, resolves to the default option (value="", option[selected], or option[value="menu_order"]) rather than leaving the dropdown in an unselected blank state.
3.11 MUTEX CONTROL

AbortController Pattern for In-Flight Request Cancellation

When users interact rapidly with faceted filters, multiple asynchronous HTTP fetches are dispatched in close succession. Without concurrency control, slower network responses can resolve out of order, overwriting newer filter states with stale catalog fragments.

Pickory eliminates network race conditions using a dual-mutex strategy in executeFilterChange():

Mechanism Implementation Concurrency Protection
AbortController Mutex if (currentAbortController) currentAbortController.abort(); Cancels the pending in-flight browser network request immediately, stopping client socket processing.
Monotonic Request ID const requestId = ++activeRequestId; if (requestId !== activeRequestId) return; Discards any asynchronous response payload whose ID does not match the latest dispatched request ID.
3.12 PAGINATION HOOK

Pagination Intercept & AJAX-Driven Page Transitions

The onPaginationClick(e) handler captures clicks on catalog pagination links (.woocommerce-pagination a) and converts them into seamless AJAX transitions:

  • Instance Scoping: Confirms the clicked link belongs to the active filter instance by checking container relationships and instance attributes.
  • Path & Query Parsing: Extracts target page numbers using regex matching on WordPress pretty permalinks (/\/page\/(\d+)\/?/) and query string fallbacks (product-page, paged, page).
  • Preservation Invariant: Invokes commitFilterUpdate with resetPage: false and source: "pagination", preserving all active facet criteria while advancing the page offset.
3.13 EVENT TRAPPING

Sort Dropdown Intercept & stopImmediatePropagation Contract

Standard WooCommerce themes attach hard page reload scripts to the woocommerce-ordering form (e.g. jQuery('.woocommerce-ordering').submit() on change).

Pickory overrides this default theme behavior through a strict event trapping contract in onSortChange(e):

  1. Intercepts the native change event on select[name="orderby"].
  2. Executes e.preventDefault() to halt form submission.
  3. Executes e.stopPropagation() to prevent bubbling to theme wrapper elements.
  4. Executes e.stopImmediatePropagation() to prevent subsequent jQuery or vanilla event listeners on the same element from firing.
  5. Commits the selected sort order via commitFilterUpdate with resetPage: true and source: "sort", executing a smooth AJAX re-order.
3.14 TEARDOWN PROTOCOL

domAbortController Listener Cleanup & Component Teardown

In Single-Page Applications (SPAs), quick-view modals, and dynamic drawer toggles, filter forms are frequently instantiated and discarded without a full page refresh. Without explicit listener teardown, dangling DOM references cause catastrophic memory leaks.

Pickory routes every single DOM listener (clicks, keydowns, changes, and submit events) through a single instance signal: { signal: domAbortController.signal }. The exported destroy() closure executes an atomic teardown:

  1. Executes domAbortController.abort(), which instantly detaches every DOM listener across the form and root containers without manual removeEventListener boilerplate.
  2. Invokes formElement._ppfxActiveFilters?.destroy() to clean active chip containers.
  3. Destroys companion mobile drawers via window.__ppfxDrawerInstance?.destroy().
  4. Removes the instance from filterFormInstances via unregisterGlobalInstance().
  5. Cancels any pending REST requests via currentAbortController?.abort() and clears debounce timers via clearTimeout(filterTimeout).
